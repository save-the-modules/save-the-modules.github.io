# Save the Modules (STM) v2.2

니케 오버로드 장비 입력·목표 관리와 규칙 기반 근사 가이드입니다. 기존 React 19 / TypeScript / Vite / Tailwind CSS 4 / Lucide 구조를 유지했습니다. 서버·계정·데이터베이스 없이 동작합니다.

## 실행

Node.js 22 이상 권장.

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

`dist/`를 정적 HTTP 서버로 제공하세요. Worker를 사용하므로 `file://` 방식은 지원하지 않습니다.

## 사용 흐름

1. 왼쪽 4부위의 옵션·단계·현재 영구 잠금을 입력합니다.
2. 최소·타협·종결 목표에서 옵션을 추가하고 줄 수와 평균 단계를 선택합니다.
3. 가이드에서 사용 가능한 모듈과 안정형 90% / 도전형 50%를 설정합니다.
4. 자동 갱신되는 빠른 행동 후보를 확인하고, 비용이 필요하면 **최적화 계산**을 누릅니다.
5. 게임 결과를 왼쪽에 반영하고 자동 갱신된 다음 후보를 확인합니다.

입력 변경은 합산·달성 상태·빠른 가이드에 즉시 반영됩니다. 비용 경로는 버튼을 눌렀을 때 Worker에서 계산합니다. 장비·목표 변경 후 이전 비용과 확률을 숨기며, 다른 장비·목표에 대한 늦은 응답도 폐기합니다. 예산·성향 변경은 같은 장비·목표의 캐시 비용을 재사용해 확률과 추천만 갱신합니다. 추천 단계가 사용자 선택을 덮어쓰지 않습니다.

## 목표와 데이터

- 9옵션 × 15단계 수치는 `src/data/tiers.ts`에서 공유합니다. 별도 전사본 `reference-transcription.json`과 원본 `docs/reference-table.png`를 테스트 자료로 보관합니다.
- 우월 코드 8단계19.35%, 4줄77.40%. 평균 단계는 합계 기준이며 각 줄의 최소 단계가 아닙니다.
- 신규 사용자의 최소 목표는 우코4줄 평균8단계입니다. 새 장비 옵션은11단계, 새 목표 옵션은8단계입니다. 평균 단계는 −/단계/+ 버튼으로 조정합니다. 기존 저장 목표에는 새 기본값을 적용하지 않습니다. 타협·종결은 빈 독립 목표이며 복사 버튼을 눌렀을 때만 이전 설정을 복사합니다.
- 크확·크뎀·크크에 같은 줄을 중복 사용하지 않습니다. 크뎀/2.88 원칙을 따르되 등록 단계는 크확의 같은 단계 값으로 정규화해 반올림 차이를 제거합니다. 전투 피해 효율 동등성을 뜻하지 않습니다.
- 사용자 최종 교정에 따라 **크확 등장12%, 크뎀 등장10%**입니다. 첨부 표의 이 두 확률만 덮어썼습니다. [출처와 검증 범위](docs/SOURCES.md)를 참고하세요.

## 근사 엔진과 제한

목표마다 현재4부위에서 독립적으로 계산합니다. 줄 수 부족과 수치 부족을 따로 구하고, 실제 목표 기여도·단계·슬롯 위치에 따른 보존 가치를 평가합니다. 완성 목표에는 사용 중단을 제안합니다.

순차 경로의 `E=c/p`를 합산하고 `P=1-exp(-B/E)`를 **예상 달성 확률**로 표시하며 정보 아이콘에서 근사 설명을 제공합니다. E=0은100%, 비용 산정 불가면 확률도 계산 불가입니다. 성향 기준을 만족하는 가장 높은 단계를 추천하며 미달 시 강제 추천하지 않습니다.

- 효과 변경은 **무잠금 첫 슬롯에서 단일 옵션을 확보하는 경로**만 계산합니다. 다른 유효 옵션을 잃는 경로는 제외하고 2·3슬롯 동시 획득 이득은 선반영하지 않습니다.
- 수치 재설정은 현재 단계를 제외한 확률을 재정규화합니다. 다른 유효 옵션의 수치를 보존할 확률까지 곱하는 슬롯별 근사입니다.
- 기존 잠금과 추가 잠금 전략을 비교합니다. 새 영구 잠금2·3개는 첫 실행에만 포함하며 기존 잠금은 이미 지불한 상태입니다. 반복 비용은 잠금0/1/2줄에1/2/3개입니다.
- **잠금 후 효과 변경 및 복수 옵션 종류의 조건부 추첨 분포는 미검증으로 제외**합니다. 우코4줄+공격력4줄처럼 복합 옵션을 새로 확보해야 하는 목표는 계산 불가가 나올 수 있습니다. 안전한 첫 행동을 찾았어도 전체 비용 산정이 안 되면 전체E/P는 제공하지 않습니다.
- 세 번째 영구 잠금, 임시 잠금권, 최초 오버로드 제작, DPS, 몬테카를로, 전체 상태공간 탐색은 미구현입니다. 최적해·실제 완료 확률을 보장하지 않습니다.

진행률은 목표별 최초 유한 기대 비용 기준 `clamp(1-current/initial,0,1)`입니다. 목표 변경 시 무효화하고 불안정한 복합 경로에서는 숨깁니다. 모듈 예산 감소로 진행률이 올라가지 않습니다.

## 저장·데모·호환성

스키마v3를 `stm-state-v3`에 자동 저장합니다. v3가 없으면 `stm-state-v2`를 변환하며 이전 키는 보존합니다. JSON 입출력과 장비/개별 목표/전체 초기화를 지원합니다. 잘못된 JSON은 거절하고 손상된 저장은 자동 덮어쓰지 않습니다.

v2 투자 예산을 새 단일 예산으로 사용합니다. 표와 일치하는 장비 직접 수치는 해당 단계로 연결합니다. 미등록 값은 검토 대상으로 남기고 단계 재선택 전 계산을 막습니다. 수동 목표 합계는 그 이상을 만족하는 가장 가까운 평균 단계로 올림 변환하며, 초과 목표나 제거된 줄별 하한은 변환 안내에 표시합니다. 정확히 같은 조건을 유지할 수 없는 경우 안내를 확인하세요.

데모는 별도 메모리 객체이며 입출력·초기화도 데모에만 적용됩니다. 종료·새로고침 시 사용자 데이터로 돌아갑니다. 같은 근사 엔진을 사용하며 기본 예산80에서 안정형은 최소, 도전형은 타협을 추천합니다. 계산 결과 자체는 저장하지 않고 진행률 기준과 UI 설정을 저장합니다.

## 코드 구성

기존 `main.tsx`에서 저장·데모·레이아웃을 유지합니다. `fastGuide.ts`와 `FastGuidePanel.tsx`는 현재 선택 목표에 대한 실시간 후보를 담당합니다. `resultCache.ts`는 데모와 사용자를 구분한 최대12개 입력 상태의 메모리 캐시와 진행률 기준 기록을 담당합니다. `controls.tsx`, `TargetEditor.tsx`, `GuidePanel.tsx`가 입력·표시를, `model.ts`가 타입·검증·합산·충족 판정·마이그레이션을 담당합니다. `engine.ts`는 순수 근사 함수, `engine.worker.ts`와 `useOptimization.ts`는 비동기 계산·오래된 결과 차단입니다. 입출력 타입은 `EngineInput`, `EngineResult`입니다.

## v2.2 빠른 가이드와 비용 계층

빠른 가이드는 비용을 산정하지 못하는 복합 목표에도 다음 행동 후보를 제공합니다. 4부위의 실제 부족 줄 수·수치를 따로 계산하고, 옵션을 제거했을 때 합산 목표가 악화되는지 검사합니다. 개별적으로 대체 가능한 크확/크뎀도 함께 제거했을 때의 손실을 재검사합니다. 무관한 옵션에는 새 잠금을 제안하지 않습니다.

기존 비용+보존점수×20 정렬은 제거했습니다. 기여 옵션 보존을 우선하고, 불가역적 새 잠금이 적은 후보를 검토하며, 같은 보호 수준에서는 기여 줄 수와 3·2·1번 슬롯의 단계로 작업 순서를 설명합니다. 비용 엔진에서는 같은 보존 위험의 계산 가능한 후보를 예상 비용으로 비교합니다. 크리티컬 대체 배정도 달성 목표 수 → 부족 줄 수 → 정규화한 수치 부족량의 순차 비교로 바꾸어 임의 보너스를 제거했습니다.

빠른 후보의 잠금은 검토 대상입니다. 비용 비교가 불가능한 조건부 효과 변경을 최적 행동으로 확정하지 않습니다. 표시하는 첫 실행 비용은 검증된 잠금·리롤 비용이며, 전체 목표의 기대 비용과 다릅니다. 기존의 무잠금 첫 슬롯 획득 및15단계 수치 재설정 확률 모델은 유지합니다. 잠금 후 종류별 조건부 분포 등 검증되지 않은 경로에는 E/P를 채우지 않습니다.

빠른 가이드는 비용 계산 전부터 사용할 수 있으며, 장비 수정 때 Worker 계산을 실행하지 않습니다. 정확히 같은 입력으로 돌아오면 비용 캐시를 재사용할 수 있습니다. 캐시는 메모리에만 존재하고 새로고침하면 사라집니다. 스키마v3·저장 키는 유지하며, 비용 모델 버전이 바뀌었으므로 이전 진행률 기준은 숨기고 새 모델의 최초 계산에서 갱신합니다. 장비와 목표 자체는 바꾸지 않습니다.
