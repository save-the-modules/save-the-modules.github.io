# Save the Modules (STM) v2.3.1

합계 목표에서 낮은 단계 채용 → 수치 재설정 경로를 추가했습니다. 특정 옵션 3종 이하에서 종류 고정/재배분 정책을 비교하고 별도 2,048회 표본으로 평균과 예산 확률을 추정합니다. 표본 오차와 계산 한도를 표시하며, 적용 범위 밖/꼬리 검증 실패 시 기존 해석적 정책을 유지합니다. 저장 스키마·배포 방식은 유지합니다.

- [원인 분석과 동일 조건 검증](docs/SUM-AUDIT.md)
- 독립 검증: `npm run validate:sums` (기본 각 8,192회, `STM_SAMPLES`로 변경)
- `npm test`, `npm run build`, `npm run benchmark`

니케 오버로드 장비 4부위의 목표 배분·잠금·리롤을 비교하는 웹 계산기입니다. React / TypeScript / Vite 기반이며 서버나 계정 없이 브라우저에서 계산합니다.

## 실행

Node.js 22 이상 권장.

```sh
npm ci
npm test
npm run benchmark
npm run build
npm run dev
```

`dist/`를 HTTP로 제공하세요. Worker 때문에 `file://`는 지원하지 않습니다.

## 사용

1. 4부위의 옵션·단계·이미 지불한 영구 잠금을 입력합니다.
2. 최소·타협·종결별 옵션 줄 수와 평균 단계를 설정합니다. 평균은 **합계 목표**이며 모든 줄의 하한이 아닙니다.
3. 사용 가능한 모듈을 입력하고 가이드에서 배분·다음 행동을 확인합니다. 장비·목표 변경 350ms 후 자동 계산하며, 오래된 결과는 숨깁니다.
4. 게임의 결과를 입력하면 현재 상태에서 다시 배분합니다. 게임 내 잠금 변경은 직접 입력해야 하며 계산기가 저장 장비를 자동 변경하지 않습니다.

`4우코+1공증+1장탄`의 공증·장탄 집중/분산 16개 배분을 비교합니다. 기존 높은 단계는 다른 부위의 목표 합계에 기여합니다. 완료 시 모듈 사용 중단을 안내합니다.

## 계산의 의미와 한계

**가정 기반의 보수적인 정책 비교이며 게임의 전역 최적해를 보장하지 않습니다.** 미확인 규칙은 결과 화면에서도 표시합니다.

- 각 부위에서 목표 전체가 뜰 때까지 반복하는 효과 변경·수치 재설정 정책과, 기준 이상 옵션을 단계적으로 채용하고 다음 실행에서 잠그는 동적 계획법 정책을 비교합니다.
- 새로운 잠금 비용과 반복 비용을 분리합니다. 기존 잠금은 이미 지불한 비용입니다. 유효 옵션의 종류와 수치를 줄이는 결과는 채용하지 않습니다.
- 기대 모듈은 해당 정책의 상태 전이 기대값입니다. 예산 내 완료 확률은 같은 정책의 **예산 DP**로 따로 계산합니다. 평균을 지수분포에 대입하던 v2.2 공식을 제거했습니다.
- 목표 종류 배분은 최대 10만 조합, 수치 배분은 균등 배분 및 유망 배치의 현재 수치·한계비용 탐색입니다. 동적으로 목표를 재배분하는 거대 MDP는 아닙니다.
- 단계적 정책은 기준 미달 목표 옵션이 섞인 결과를 거절하고, 기준 이상 목표 옵션은 다음 실행에서 잠급니다. 낮은 단계 옵션을 먼저 모아 수치작으로 전환하는 모든 경로, 잠금 해제, 임시 잠금권은 탐색하지 않습니다. 더 저렴한 전략이 있을 수 있습니다.
- 비용과 확률은 표시된 배분 정책을 계속 따르는 경우입니다. 실제 결과를 입력하여 배분을 바꾸면 이후 정책과 분포가 달라집니다. 현재 초과 수치는 반영하지만 미래 초과 수치의 추가 이득은 선반영하지 않습니다.

설계·식·상태 압축의 근거는 [엔진 문서](docs/ENGINE.md), 가정과 사용자 확인 사항은 [규칙 출처](docs/SOURCES.md), 측정 결과는 [QA](QA.md)를 참고하세요.

## 호환성과 배포

- 스키마 v3, `stm-state-v3`, v2 가져오기, JSON 입출력, 장비·목표 편집, 데모 분리를 유지합니다.
- 135개 수치와 사용자 교정 확률(크확 12%, 크뎀 10%)을 유지합니다. 크크는 크확/크뎀의 동일 단계를 동등하게 취급하고 줄 중복 배정을 금지합니다.
- 모델 버전을 변경해 이전 비용·진행률 기준은 사용하지 않습니다. 제한된 탐색에서 비용 비율을 실제 진행률처럼 표시하지 않습니다.
- Worker, 12개 입력 상태 캐시, 요청 취소와 오래된 응답 차단을 유지합니다. 예산 변경은 비용 정책을 재사용해 확률만 다시 계산합니다.
- `.github/workflows/deploy.yml`을 유지합니다. main push 시 `npm ci`, 테스트, 빌드 후 GitHub Pages에 배포합니다. 상대 경로 설정과 Worker 청크를 보존합니다.

## 구성

`rules.ts`: 조건부 추첨 가정과 확률 / `retention.ts`: 단조로운 획득·잠금 DP / `planner.ts`: 4부위 배분과 수치 후보 탐색 / `probability.ts`: 정책 기대값·예산 DP / `engine.ts`: 결과 구성 / `useOptimization.ts`: 자동 Worker 갱신 / `model.ts`: 저장·검증·합계·달성 판정.
