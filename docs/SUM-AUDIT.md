## 원인별 판단

- **목표 조건:** `model.ts` 종료 판정은 실제 합계였지만 기존 `planner.ts`는 최소 단계로 분해하고 `retention.ts`는 그 기준 미달 종류를 통째로 거절했다. 즉 판정과 비용 정책의 허용 범위가 달랐다. 새 정책은 실제 합계를 매 실행 반영한다. 우코 1·15·8·8의 77.40% 회귀 검증 포함.
- **추첨 확률:** 수정하지 않았다. 기존 해석식 326.61을 독립 추첨 326.09±3.23이 재현했다. 이번 격차의 주원인을 추첨 구현 오류로 볼 증거는 없다. 순서 역전 민감도는 기존 정책 약 327.43으로, 큰 격차를 설명하지 못한다. 순서·독립성·조건부 재정규화는 여전히 가정이다.
- **잠금 정책:** 기존 정책은 기준 이상 확보 후 영구 잠금을 강제한다. 새 경로는 낮은 줄을 먼저 재설정하고 현재 전체 합계 분담량을 채운 뒤 잠글 수 있다. 새 잠금 2/3개는 실행 때 한 번, 리롤 1/2/3개는 매번. 잠금 해제는 탐색하지 않는다.
- **채용 정책/행동:** 가장 큰 요인이다. 326.6→117.6은 개별 8단계 조건을 유지해도 발생한다. 낮은 유효 종류를 수치 재설정으로 개선하는 경로가 기존 단계적 정책에서 빠져 있었다. 여러 변경을 포함한 정책 비교이므로 각 개별 규칙의 엄밀한 인과 기여량으로 해석하면 안 된다.
- **합계/초과 수치:** 같은 종류 고정 경로에서 117.6→106.1. 낮은 줄도 채용하며 실제 높은 값으로 잔여 분담량을 낮춘다. 단계 평균 대신 소수 둘째 자리 실제 표를 사용한다.
- **탐색 범위:** 이 목표의 종류 배치는 16개다. shortlist 1/32/100000, refinement 켬/끔 모두 326.6146이었다. 따라서 이 사례에서 상위 32개 탈락이 원인은 아니다. 기존 한계비용 단계 탐색의 최적성을 증명한 것은 아니며, 다른 목표에서는 불균등 배분을 놓칠 수 있다. 새 정책은 고정 단계 조합을 사전 선택하지 않는다.
- **적응형 종류 배치:** 구현한 재선택 휴리스틱은 이 사례에서 오히려 비쌌다. 현재 확보 종류 수와 수치를 최대화하는 배치가 미래 리롤 비용을 최소화하지는 않는다. 그래서 이를 무조건 채택하지 않고 고정 종류/적응형 합계 정책과 비교한다. 전역 적응형 Bellman 최적해와 비교했다는 뜻이 아니다.

추가로 `scripts/audit-tiers.ts`는 기존 정책이 고른 분산 배치(우코+공격 3부위, 우코+장탄 1부위)에 대해 불균등 단계 배분의 경계 **554,555조합을 전수 비교**했다. 해당 배치/기존 정책 내 최저는 여전히 전부 8단계의 326.6146이었다. 최소 단계 비용의 단조성을 이용해 마지막 우코·공격 단계는 합계를 충족하는 최소 단계만 검사한다. 이것은 다른 종류 배치까지 포함한 전역 최적성 증명은 아니지만, 기준 사례의 선정 배치에서 더 싼 불균등 단계 조합을 놓친 것이 아니라는 직접 증거다.

## 외부 계산기와의 비교 한계

사용자 스크린샷은 110.4개, 150개 내 89.9%, P50 107, P90 151을 표시한다. [외부 계산기](https://nikke-optimizer.pages.dev/)의 2026-10-18 공개 설명은 합계 T조합 후보를 탐색한 뒤 선택 배분의 기대값/CDF를 계산하며, 초과 수치를 모두 선반영하는 전역 MDP는 아니라고 명시한다. 또한 영구 잠금 해제까지 비교한다고 설명한다.

초기 입력과 목표 표시값은 정렬했지만 외부 구현/정책/표본을 독립 검증하지 않았다. 외부는 상위 목표 줄 합계를 설명하고, STM은 기존 저장 데이터 의미대로 **최소 줄 수 + 해당 종류 전체 줄의 실제 합계**를 쓴다. 목표보다 많은 동일 종류 줄이 생기면 이 차이도 영향을 줄 수 있다. 그래서 106.1이 110.4보다 정확하거나 최적이라는 결론을 내리지 않는다. 게임 규칙은 외부 숫자에 맞춰 변경하지 않았다.

## 대표 목표와 성능

별도 독립 시뮬레이션: 4우코 평균 27.39±0.24개, 4우코+1공격+1장탄 67.63±0.60개, 복합 12줄 T8 327.62±2.88개. 모두 8,192회 완료. 빈 초기 슬롯과 명중률 1줄 초기 상태는 같은 난수에서 동일한 완료 비용을 냈다(비목표 수치는 의사결정에 사용하지 않음).

`benchmark-v2.3.1.jsonl`: Windows / Ryzen 5 5600 / Node 24.19.0, 1회 cold + 7회 재계산. 중앙값: 4우코 318ms, 6줄 605ms, 기준 8줄 963ms, 12줄 T8 1,576ms. 측정 중 독립 검증도 실행되어 CPU 경합이 포함될 수 있다. UI는 Worker에서 계산하며 예산 변경만으로는 다시 시뮬레이션하지 않는다. 12줄 T15는 표본 실행 한도로 새 경로를 채택하지 않고 기존 해석적 결과를 유지한다.

## 신뢰 범위

모의실험의 추첨과 실행 루프는 제품 구현과 분리했지만, 의도적으로 동일 정책의 결정/채용 함수를 공유한다. 최종 성공은 UI `achievement`로 별도 검증한다. 따라서 정책 구현의 모든 버그를 독립적으로 배제하는 증명은 아니다. 기존 정책은 원시 추첨으로도 검증했다.

표본 없는 꼬리의 존재를 배제하지 못하며 근사 신뢰구간은 미검증 게임 규칙 오차를 포함하지 않는다. 중도 미완료를 버려 평균을 낮추지 않는다. 특정 옵션 4종 이상, 혼합 크리티컬, 표본 한도 초과는 기존 해석적 경로를 유지한다. 입력마다 정책을 다시 선택하면 고정 정책 분포와 달라질 수 있다. 기존 저장 스키마 3, localStorage 키, 사용자 UI, Pages 워크플로는 유지했다.
