# v2.3.2 크리티컬 및 옵션 경계 검증

2026-10-20. 초기 장비는 부위별 1번 슬롯 우코 7·7·1·6단계, 다른 슬롯 빈칸, 잠금 없음. 모든 목표는 평균 T8 상당의 실제 합계다.

## 원인과 수정

기존 합계 정책은 특정 옵션 3종까지만 지원하고 크크를 제외했다. 따라서 4우4공4크확/4크뎀은 합계 보완 정책을, 2크확2크뎀/4크크는 개별 기준을 사용하는 해석적 대체 정책을 비교하고 있었다. 3배 차이는 같은 수준의 전략 탐색 결과가 아니었다.

4종까지 합계 정책을 확대하고 크크를 어느 종류든 채용하는 논리적 요구로 처리했다. 실제 추첨에서는 크확 12%, 크뎀 10%를 별도로 유지한다. 확률·단계표·잠금 비용은 변경하지 않았다. 둘을 하나의 22% 옵션으로 추첨하지 않으며, 같은 장비의 크확과 크뎀 동시 등장도 유지한다.

크크의 진짜 최소 비용은 같은 조건의 4크확/4크뎀 최소 비용보다 클 수 없다. 더 좁은 목표를 끝내는 전략을 그대로 쓸 수 있기 때문이다. 다만 제한된 휴리스틱과 표본 추정 결과가 모든 입력에서 이 부등식을 보장하지는 않는다.

|---|---:|---:|---:|---:|
| 4크확 | 347.5 | 347.5 | 342.8 ±2.8 | 1.98% |
| 4크뎀 | 374.6 | 374.6 | 370.4 ±3.1 | 1.49% |

| 4크크 | 1138.5 | 307.4 | 305.9 ±2.7 | 5.42% |

별도 실행은 각 8,192회. 4크확과 2크확2크뎀의 평균 차이는 오차 범위 내이므로 혼합이 확실히 저렴하다고 결론내리지 않는다. 미완료 경로 0. 계산 첫 실행 약 1.55–1.80초. 원시 결과: [critical-validation-v2.3.2.jsonl](critical-validation-v2.3.2.jsonl).

## 검증의 범위

별도 시뮬레이터는 난수 생성기·원시 추첨·비용 실행 루프를 따로 작성했지만 정책 선택/채용 함수는 공유한다. 추첨 및 실행 구현의 대조이며 정책 최적성의 독립 증명은 아니다. `npm run validate:critical`, `npm run validate:edges`로 재현할 수 있다.

크크는 배치당 부위별 한 줄을 약속하는 제한 정책이다. 여분 크리티컬이 다른 두 목표의 확보를 방해하는 보존 의무가 되지 않게 처리하고 실제 달성 판정에는 모든 줄을 센다. 물리적 잠금 두 개는 두 슬롯을 점유한다. 크크와 특정 크리티컬 동시 요구, 크크 5줄 이상, 목표 5종 이상은 기존 해석적 정책으로 돌아간다. 추첨 순서·독립성·재정규화 가정과 잠금 해제 미탐색 한계는 그대로다. 전역 최적해로 표시하지 않는다.
